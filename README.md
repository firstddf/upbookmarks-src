# upbookmarks

**把浏览器书签和设置加密后备份到自己的 Gitee 私有仓库。**

数据存在你自己账号下的私有仓库里，加密和解密都在本地完成。没有中间服务器，没有账号体系，
也没有任何人能替你打开备份。

---

## 为什么需要它

如果你遇到过这些情况，这个工具就是为你写的：

- **Firefox 中国版账户同步已于 2025-09-29 终止**，云端数据被删除，跨设备同步没了；
- Firefox 国际版 Sync 与 Chrome 的云同步在国内**时通时不通**，备份这种要求确定性的事情不能靠它；
- 浏览器自带的"导出书签为 HTML"只能手动做，**没有历史版本**，导错了也找不回；
- 想在**两台电脑**之间搬书签，或者想在换机、重装系统前留一份可控的存档。

自建同步服务器能做到，但要维护一整套服务；把书签丢进网盘虽然简单，**却是明文的**。

upbookmarks 走的是另一条路：**在本地加密，然后把密文存进你自己的 Gitee 私有仓库。**

## 功能

### 书签备份与还原

- 完整保留文件夹层级与添加时间；
- 每台机器独立目录，**不会互相覆盖**（这点是结构上保证的，不是靠约定）；
- 云端保留最近 20 份快照，可以回到任意一个历史时间点；
- 还原前有**差异预览**（会新增几条、会删除几条），确认后才执行；
- 还原前自动把当前书签**另存一份**，万一还原错了可以一键找回。

### 设置备份（Firefox）

备份主页、新标签页、图片动画、JavaScript 开关等一批浏览器设置。
**读不到的项会如实标注"未还原"，绝不悄悄改成默认值**——这是刻意的。

> Chrome / Edge 没有对应接口，**该平台只支持书签**。界面上会明确告诉你，不会假装成功。

### 自动备份

- 定时检查（默认每 60 分钟，可调）；
- **书签或设置一有改动就自动上传**（静默 5 分钟后触发，连续编辑不会产生一堆快照）；
- 需要先启用下面的「信任此设备」。

### 跨浏览器迁移

Firefox 与 Chrome 的书签结构不同（Chrome 没有「书签菜单」）。跨浏览器还原时，
upbookmarks 会自动做映射与去重：**书签不会丢**，但文件夹层级可能被重新归置——预览时会明确警告。

### 加密与恢复

- 主口令 → PBKDF2（60 万次）→ 包裹一把随机数据密钥 → AES-256-GCM 加密每条快照；
- **两条并列的解锁路径**：主口令（日常）与恢复码（应急）；
- **换主口令不需要重新加密历史快照**，旧备份照旧可读；
- 恢复码**只显示一次**，请离线保管。

### 「信任此设备」

省掉反复输口令的麻烦：口令会被**不可导出的设备密钥加密后**存在本机，
默认**3 天不活动**就要求重新输入（上传或还原会刷新计时）。

## 安装

### 从 Release 下载（推荐）

**Chrome / Edge**

1. 下载 `upbookmarks-chrome-*.zip`，**解压**到任意目录（例如 `D:\upbookmarks`）
2. 打开 `chrome://extensions`，右上角打开**开发者模式**
3. 点「**加载已解压的扩展程序**」→ 选中**解压出来的那个目录**

> 注意：选**目录**，不是 zip 文件本身。

**Firefox**

1. 先在 `about:config` 里把 **`xpinstall.signatures.required` 设为 `false`**
2. 下载 `upbookmarks-firefox-*.xpi`
3. `about:addons` → 右上角齿轮 ⚙ → 「**从文件安装附加组件**」→ 选该 `.xpi`

> 本扩展未签名。`xpinstall.signatures.required = false` **只在 Nightly / Developer Edition / ESR 上被尊重**；
> Release 版无法安装未签名扩展。

### 从源码构建

```bash
node tools/build.mjs        # 产出 build/firefox/ 与 build/chrome/
```

再按上面的方式加载 `build/firefox` 或 `build/chrome`。

## 配置（第一次使用）

### 1. 建一个私有仓库

在 Gitee 上新建一个仓库，**必须选「私有」**。名字随意，例如 `upbookmarks`。

> 扩展会在上传前检查仓库可见性，**公开仓库会被拒绝上传**。

### 2. 生成访问令牌

到 <https://gitee.com/profile/personal_access_tokens> 新建一个令牌：

- **权限只勾 `projects`**（不要勾 `user_info`，不要勾组织权限）
- 生成后**立刻复制**——它只显示这一次

### 3. 填写并解锁

1. 打开扩展的**选项页**（点工具栏图标，或 `about:addons` 里点「首选项」）
2. 第 1 段填：仓库所有者、仓库名、令牌、本机名称（如 `desktop`）
3. 点「保存配置」
4. 第 2 段出现「**首次建立仓库**」→ **设一个主口令**（口令短语，≥6 段，每段 ≥2 个字符）
5. 点「首次建立仓库」→ **当场抄下恢复码**（只显示一次）

**主口令与恢复码是两个不同的东西：**

| | 用途 | 什么时候用 |
|---|---|---|
| **主口令** | 日常解锁 | 每次打开选项页做备份/还原 |
| **恢复码** | 应急解锁 | **只有忘记主口令时**才用 |

> ⚠️ 恢复码请抄在纸上，或存在**与 Gitee 无关**的地方（手机密码管理器、离线笔记）。
> **不要存进 `upbookmarks` 这个仓库里**——那等于把钥匙和锁放在一起。

### 4. 开始备份

点「上传本机快照」，第一份备份就完成了。之后可以：

- 手动点「上传本机快照」；
- 或启用第 3 段的「**自动备份**」（需先启用「信任此设备」）。

## 换电脑 / 换浏览器恢复

```
1. 在新机器上装好扩展，填同一个 仓库 + 一个新的令牌
2. 用同一个主口令解锁        ← 令牌可以不同，主口令必须相同
3. 「刷新云端快照」→ 选中来源 → 「预览还原」看差异 → 「执行还原」
```

**建议每台机器用不同的机器名**（`desktop` / `laptop` / `office-pc`），
云端快照会按机器分目录，一眼能看出哪份来自哪台。重名会被检测并提示。

**关于令牌**：每台机器可以各用一个，也可以共用一个。
各用一个是更省心的做法——哪台机器不用了就删那一个令牌，其他不受影响。

## 关于密码（重要）

**本扩展不备份密码，也无法备份。**

这不是偷懒——**Firefox 根本没有向扩展提供读取密码库的接口**，Chrome 的对应接口也只对内置组件开放。
任何声称"能一键备份你的浏览器密码"的扩展，要么在骗你，要么在偷你的密码。

密码请交给专门的密码管理器：

1. 用 **KeePassXC** 建一个 `.kdbx` 库，设一个主口令；
2. 从浏览器导出密码为 CSV，导入 KeePassXC（这是行业通用做法）；
3. 把 `.kdbx` 文件**直接放进同一个 Gitee 私有仓库**；
4. 手机上装 **KeePassDX** 或 **Keepass2Android**，同一个库就能应急打开。

扩展完全不认识这个文件，只当它是仓库里一个普通的二进制文件。

## 安全说明

**能防住**

- Gitee 服务端、其内部人员、或其被入侵后读取仓库 —— 仓库里只有密文；
- 仓库被误设为公开、被镜像 —— 密文公开也不等于泄漏；
- 账号或令牌泄漏 —— 仍需要主口令才能解密；
- 不同机器之间互相覆盖数据 —— 结构上不可能。

**防不住**

- 本机被入侵、被植入键盘记录；
- 主口令被社工、钓鱼或肩窥；
- **忘记主口令且丢失恢复码 —— 数据永久不可恢复**；
- Gitee 封禁账号或仓库下架（建议另留一份离线副本）。

**一句必须说清的话**

> 本项目**不提供任何"验证身份即可恢复密钥"的通道**。
> 这不是缺陷，而是设计的前提：任何这样的通道，同时也是攻击者最想走的路。

完整的威胁模型见 [01-threat-model.md](01-threat-model.md)。

## 展望

### 近期

- [ ] **上架扩展商店**：目前只能手动加载，安装门槛偏高。AMO 与 Edge 附加组件商店仍在审核范围之外
      （Chrome 网上应用店对"需要用户自备令牌"的扩展限制较严）；
- [ ] **收窄令牌权限**：Gitee 的个人访问令牌是账号级的，无法限制到单个仓库。
      若 Gitee 未来提供仓库级可写凭据，本项目会第一时间支持；
- [ ] **网页端恢复查看器**：一个纯静态页面，把 `.enc` 拖进去、输入主口令即可查看，
      方便在没装扩展的电脑上应急取回书签。

### 中期

- [ ] **多后端支持**：目前只支持 Gitee。计划把存储层抽象出来，支持 WebDAV（坚果云等）、
      S3 兼容存储、以及本地目录；
- [ ] **书签合并策略**：现在的选择是"整树替换"或"追加"。计划增加真正的三方合并，
      让两台机器都能新增书签而不丢失任何一方；
- [ ] **增量快照**：只上传变化的部分，减小仓库体积增长；
- [ ] **快照加密的端到端验证工具**：给怀疑数据安全的人一个可自行验证的脚本。

### 长期

- [ ] **同步历史浏览记录与打开的标签页**；
- [ ] **浏览器内的恢复演练**：定期提示用户验证恢复码是否有效（"没演练过的备份不算备份"）；
- [ ] **审计报告**：请第三方对加密实现做一次独立审查。

**不会做的事**

- ❌ 不做"服务器帮你找回密钥"；
- ❌ 不上传明文，也不提供"跳过加密"的开关；
- ❌ 不读取、不备份密码；
- ❌ 不引入任何账号体系或遥测。
